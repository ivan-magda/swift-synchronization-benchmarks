## Method and experiment 1 regression

The inspected executable is the second signed artifact above. Symbol lists,
complete assembly, indirect-symbol tables and per-function comparisons stay
under ignored `build/private/phase-2-acceptance/`. Commands use the recorded
repository-relative artifact path:

```bash
xcrun nm <executable> | xcrun swift-demangle
xcrun llvm-objdump --macho --mattr=+lse,+rcpc \
  --no-show-raw-insn --disassemble <executable>
xcrun llvm-objdump --macho --indirect-symbols <executable>
```

The LSE/RCpc features matter: without them the disassembler prints six atomic
instructions as `.long`. Imported calls were resolved using Mach-O indirect
symbols rather than the nearest-symbol labels in a generic disassembly.

The comparison uses the actual clean signed iOS 26 phase-1 artifact
`b2c9f9dae09c-clean-ios26-20261105T094500Z`. All 101 previously recorded selected
function entries retain their instruction counts, imported-call sequences and
`swift_beginAccess`/`swift_endAccess` counts. All 66 experiment-1 loop entries
also retain their instruction-mnemonic sequences, including async resume paths.
This checks operation and instrumentation structure, not byte-identical binaries
or equal runtime distributions; addresses and layout change in the larger app.

## Experiment 7 caller paths

`Mutex.withLock` and `MutexCounter.increment()` are inlined in the
`fromBackgroundTask` counted loop. At `0x100024ea4` the loop directly calls
`os_unfair_lock_lock`, loads/adds/stores the integer, calls
`os_unfair_lock_unlock`, and repeats. It contains no counter or `withLock`
function call, allocation or per-operation Swift access check.

`CounterActor.incrementAsync()` is also inlined in `onActor`. More than the
call disappears: the compiler folds the sub-batch's increments into one
load/add/store at `0x10001d468`–`0x10001d474`. This path measures no
per-operation async call. The surrounding async resume paths still invoke
`swift_task_switch` when entering and returning from each operations closure;
these are executor handoffs around a sub-batch, not one hop per increment.
The pilot must treat this row as optimized code already on the actor, with
batch-envelope costs amortized over the requested operation count. It cannot
be presented as the cost of an uninlined async method call.
